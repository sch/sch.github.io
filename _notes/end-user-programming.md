End-user programming is the ideal that we can modify, script, and extend the
software we use day-to-day to fulfill our needs, instead of treating apps as
appliances.

It's a [guiding principle][Ink and Switch] of the research group Ink & Switch to
create software with these properties. It's an extension of systems like Excel,
Hypercard, and HTML to deliver the source with the content. Melanie Hoff argues
that any interactions with the computer [should be considered
programming][Always Already Programming].

Some have experimented with end-user programming at the operating system level.
The [User-Tailorable Systems] experiment was a windowing system that surfaced
contextual buttons that would invoke lisp code, so you could automate common
tasks on top of the existing UI. [Viewpoints] set up a visually oriented system
so that common operations could be performed on raw pixel info instead of
internal data structures.

Patrick Dubroy's distinction is on [casual programming]: most things are
possible for a professional programmer to automate, but aren't worth the hassle.
His examples include calendar and alarm management, website link management, and
personal finance tasks.
